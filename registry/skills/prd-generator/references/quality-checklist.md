# PRD Quality Checklist

## Completeness

- [ ] Executive Summary provides clear project overview
- [ ] Problem Statement is specific (not generic)
- [ ] 5+ measurable goals defined
- [ ] 3+ personas with goals, pain points, and context
- [ ] 15+ functional requirements
- [ ] 4+ NFR categories addressed
- [ ] Integration points documented
- [ ] Constraints and assumptions listed
- [ ] Success metrics are quantifiable
- [ ] Scope boundaries clearly defined
- [ ] Risks have mitigation strategies

## Quality

- [ ] Requirements use "shall" or "must" language
- [ ] Each requirement is independently testable
- [ ] No ambiguous terms ("fast", "easy", "user-friendly") without metrics
- [ ] Personas are realistic, not stereotypes
- [ ] NFRs include specific thresholds (e.g., "< 200ms response time")

## Traceability

- [ ] Requirements are numbered for cross-referencing
- [ ] Personas map to functional requirements
- [ ] Success metrics map to goals
