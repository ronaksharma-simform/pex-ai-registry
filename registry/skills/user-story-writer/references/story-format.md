# User Story Format Specification

## Story Structure

Each user story follows this template:

### [US-{number}] {Title}

**As a** {persona}
**I want** {action/capability}
**So that** {benefit/value}

**Acceptance Criteria:**

- Given {context}, when {action}, then {expected result}
- Given {context}, when {action}, then {expected result}
- Given {context}, when {action}, then {expected result}

**Edge Cases:**

- {edge case description}

**Priority:** Must Have | Should Have | Could Have | Won't Have
**Story Points:** {1|2|3|5|8|13}

## Priority Guidelines (MoSCoW)

- **Must Have:** Core functionality, blocking for launch
- **Should Have:** Important but not blocking
- **Could Have:** Nice-to-have, implement if time allows
- **Won't Have:** Explicitly excluded from this iteration

## Story Point Scale

- **1:** Trivial change, < 2 hours
- **2:** Small task, half day
- **3:** Standard task, 1 day
- **5:** Complex task, 2-3 days
- **8:** Large task, 3-5 days
- **13:** Epic-level, needs decomposition
